# 今日焦点与任务专注 PRD

日期：2026-09-11。状态：交互规则草案，等待视觉方向选择；尚未实施。

## 目标与依据

让用户从既有四分类待办选出当前值得投入的事情，并从首页直接启动关联计时。目标用户暂定为同时处理课程、写作、开发与日常事项的个人用户，此假设待试用验证。

依据：README.md 的首页、待办、番茄钟与首页组件显隐规则；renderer/app.js 的待办持久化与番茄钟实现；renderer/styles.css 的设计变量。仓库截图仅作历史视觉参考，不作为当前运行验收证据。

## 首版范围

- 新增可隐藏的今日焦点首页组件；待办页提供设为／移出今日焦点操作。
- 最多三项未完成焦点。完成后释放名额，当日完成项在组件内折叠展示；次日不再展示昨日完成项，但原待办记录不受影响。
- 焦点引用原任务，名称、分类、截止日期和完成状态保持同步。
- 首页每项提供开始专注，复用现有番茄钟及用户保存的时长。同一时刻只能有一个计时会话。
- 用户主动选择任务；不自动按截止日期填满三个名额。
- 不调整四分类 2 × 2 布局、不更改默认截止时间、不扩展折叠态、不增加统计排行榜或云端服务。

## 主要流程

1. 待办行操作「设为今日焦点」→ 原任务保留 → 首页显示对应任务。
2. 首页「开始专注」→ 使用已有时长设置 → 计时开始，关联任务显示正在专注。
3. 暂停／继续在焦点组件与番茄钟间同步；收起面板不暂停。
4. 时间到 → 单次非抢焦点提醒 → 会话进入待处理状态。
5. 用户选择「完成任务」「再专注一轮」或「稍后处理」。完成任务同步原待办；再来一轮沿用任务和设置时长；稍后处理结束本轮但保留焦点。

## 页面状态与文案

| 状态 | 展示与操作 | 规则 |
| --- | --- | --- |
| 无焦点 | 今天先推进哪件事？／从待办选择 | 跳到待办页；无待办时展示现有新增入口 |
| 已选 1–3 项 | 名称、分类色、明确的截止日期、开始专注 | 列表按选入顺序稳定展示，不因临近截止重排 |
| 名额已满 | 已有 3 项今日焦点，移出一项后再添加 | 不自动替换，也不删除任何任务 |
| 正在专注 | 当前任务、剩余时间、暂停 | 只有一个活动会话；普通番茄钟入口控制同一会话 |
| 已暂停 | 计时已暂停／继续／结束本轮 | 不累计暂停时间 |
| 本轮结束 | 本轮专注结束／完成任务／再专注一轮／稍后处理 | 时间到不等于任务完成 |
| 跨日未完成 | 昨日保留／继续保留／移出今日 | 不自动延期、不清空未完成任务 |
| 已逾期 | 明确显示已逾期与日期 | 不只依靠颜色表示；允许继续专注 |
| 全部完成 | 今天选定的任务已完成／继续选择 | 不自动补入其他任务 |

## 并发操作与异常

- 在另一任务上点击开始时，若已有活动或暂停会话，展示「正在专注于…」，选择返回原会话或结束并切换；取消不改变现状。
- 普通番茄钟正在计时也适用上述冲突规则，不悄悄覆盖现有计时。
- 移出正在专注的任务仅移出焦点列表；当前计时仍保留任务关联，可从番茄钟继续操作。
- 删除关联任务后，计时作为普通计时继续；提示关联任务已删除，结束时不提供完成该任务的操作。
- 从待办页直接完成正在专注的任务时，同步状态，计时继续为普通计时，避免再次完成或产生重复提醒。
- 隐藏焦点或番茄钟组件不停止计时。设置页可恢复组件；再次开始专注时始终识别已有会话。
- 休眠期间按实际经过时间计时；唤醒后若已到点，仅触发一次结束提醒，不连发。
- 正常重启或崩溃恢复后保留关联与状态：尚未到点继续倒计时，已到点显示待处理，不补播旧弹窗；暂停状态保持暂停。
- 写入失败明确提示未保存并保留原状态，不能展示保存成功。
- 切换工作区时保存原工作区会话，新工作区只加载自己的会话；恢复原工作区按上述重启规则处理。

## 数据与平台约束

- notch-todo-data 与 P0–P3 原结构不变；独立增加版本化焦点关系与会话记录，以稳定任务 ID 关联。
- 记录焦点日期、顺序、任务 ID；计时记录关联 ID、状态、剩余时长或目标结束时间、结束处理状态。日期按系统本地日期计算，计时不受时区切换影响。
- 焦点和会话元数据应纳入现有工作区保存／恢复路径；旧工作区缺少新字段时显示空焦点，不自动创建示例任务。
- 首页新增组件要一并扩展组件注册、显隐和自动布局规则；保留现有组件顺序与尺寸偏好，不通过重置布局迁移。已存在的组件显隐规则不被覆盖。
- 新用户首次启用焦点组件；已有用户在待办首次选择焦点时提示可在设置中显示。用户已明确隐藏时不自动恢复。
- macOS 与 Windows 具备相同任务与计时功能；不依赖当前窗口、汽水音乐或系统应用聚焦能力。
- 内容区保持 1240 × 540，窗口保持贴顶居中，矮屏和窄屏遵守既有安全距离。镜子若显示仍保持方形，不改变设备权限与资源释放规则。

## 视觉探索与原型范围

探索三个候选，均使用既有黑灰表面、系统字体、18px 组件圆角、8pt 间距以及四类状态色；选择后仅实现一个方向。

- 首页卡片：在既有 Bento 首页提供中等尺寸的焦点清单，计时仍主要显示在原番茄钟组件。
- 列表与计时并排：一个宽组件左侧列出焦点，右侧强调当前任务与计时；其他首页组件沿用显隐和重排能力。
- 单任务聚焦：焦点组件优先展示选中任务与主按钮，其余两项以紧凑待选列表展示，保持用户可见的切换入口。

选定后的交互原型覆盖：空状态、选择三项、名额上限、开始、暂停、继续、冲突切换、结束三个选项、跨日保留、任务删除。原型使用独立样本数据，不读写真实工作区。图像概念只代表主要界面，不能当作这些交互已实现。

## 验收与验证计划

1. 已有焦点时，从首页到开始计时不超过两次点击。
2. 首页和待办间名称、完成、删除同步；满额不写入第四项。
3. 计时在收起、隐藏、休眠、重启后遵守上述规则，且不会重复结束提醒。
4. 完成、再来一轮、稍后处理都具有唯一且可复现的状态转换。
5. 键盘可访问所有操作，焦点可见；状态有文字，不仅靠颜色；中文长标题不挤掉主操作。
6. 两平台布局和工作区迁移保持已有契约，旧数据加载正常。
7. 先用真实任务试用一周，对比打开面板到开始工作的耗时，目标中位数较基线下降 30%；这是待验证目标，不是已取得结果。可采用人工记录，不默认新增遥测。

实施后进行与状态恢复及关联行为相称的验证；build、lint 依项目规则另行取得明确确认。本次文档与视觉提案不执行这两项。
